# AI Use Log (<vndt4>)

- **Tool used:** Gemini
- **Purpose:** To assist in implementing and integrating `config.py` (`Settings`, `load_dotenv`, `load_settings`) and `logging_setup.py` (`JsonFormatter`, `get_logger`), and extending them so `get_logger` dynamically applies `Settings.log_level` while strictly protecting sensitive configuration values (`llm_api_key`) and filtering structured JSON log fields.
- **Prompt used:** "I am working on `config.py` and `logging_setup.py` in `assistant_core`. Please extend my code so `Settings` validates `log_level` and hides `llm_api_key` from string representations, and update `get_logger` in `logging_setup.py` to accept a configurable log level while outputting structured JSON logs to stderr. Include pytest unit tests."
- **Evaluation:** The AI generated the Pydantic `Settings` model, `.env` loader, and `JsonFormatter` class quickly. However, I found three issues during manual review: (1) in `config.py`, `llm_api_key` was defined without `Field(default=None, repr=False)`, which risked exposing the secret key if the `Settings` instance was printed or logged; (2) in `logging_setup.py`, the AI initially merged arbitrary `record.__dict__` attributes into the JSON output instead of restricting them to `ALLOWED_KEYS = ("intent", "latency_ms", "session", "degraded")`; and (3) `get_logger` attached `StreamHandler(sys.stdout)` unconditionally without checking `if not logger.handlers:`, which mixed logs with CLI answers on `stdout` and duplicated log lines across test runs. After I manually added `repr=False` to `llm_api_key`, enforced the `ALLOWED_KEYS` whitelist, switched to `StreamHandler()` (`stderr`) with an idempotent handler guard, and set `logger.propagate = False`, all unit tests and `ruff check` passed cleanly.
